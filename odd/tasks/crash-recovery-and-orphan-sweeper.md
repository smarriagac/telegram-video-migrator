# Task: Crash Recovery, Orphan Sweeper & Self-Healing Pipeline

## Problem Statement
When the backend container or process terminates unexpectedly (SIGTERM, container restart, host crash, OOM kill, unhandled task crash):
1. In-flight jobs (`migration_jobs`) in status `RUNNING` become zombie jobs without an active execution loop.
2. In-flight queue items (`migration_queue`) in status `IN_PROGRESS` remain locked in that state, blocking completion, clean retries, or resuming.
3. In-flight scheduled broadcasts (`scheduled_broadcasts`) in status `RUNNING` remain permanently stuck in `RUNNING`.
4. In-flight video processing jobs (`video_processing_jobs`) in status `PROCESSING` remain permanently hung.
5. Incomplete, partial, or orphaned media files (`tmp*.mp4`, `tmp*.part`, `tmp*.jpg`, etc.) generated by `tempfile` linger in the host/container `/tmp` directory, wasting disk space.
6. Administrators receive no notification or audit record indicating that a crash occurred and which entities were rescued.

## Target Architecture & Design
1. **Repository Layer Reconcilers (`JobRepositoryPort`)**:
   - `reconcile_orphaned_jobs() -> int`: Sets `RUNNING` -> `PAUSED` in `migration_jobs` (existing).
   - `reconcile_orphaned_queue_items() -> int`: Sets `IN_PROGRESS` -> `PENDING` in `migration_queue`.
   - `reconcile_orphaned_broadcasts() -> int`: Sets `RUNNING` -> `SCHEDULED` in `scheduled_broadcasts`.
   - `reconcile_orphaned_video_processing_jobs() -> int`: Sets `PROCESSING` -> `FAILED` with explanation in `video_processing_jobs`.
   - Implementations for both [`SqliteJobRepository`](file:///home/sm/proyectos/telegram-video-migrator/backend/infrastructure/persistence/sqlite_job_repository.py) and [`PostgresJobRepository`](file:///home/sm/proyectos/telegram-video-migrator/backend/infrastructure/persistence/postgres_job_repository.py).

2. **Disk Orphan Sweeper (`DiskOrphanSweeper`)**:
   - Safely cleans up stale temporary files in the temp directory matching migration/transcoding prefixes (`tmp*.mp4`, `tmp*.part`, `tmp*.jpg`, `tmp*.png`, `tg_video_*`).
   - Computes total bytes freed and files deleted.

3. **Self-Healing Application Service (`CrashRecoveryService`)**:
   - Located at [`backend/application/services/crash_recovery_service.py`](file:///home/sm/proyectos/telegram-video-migrator/backend/application/services/crash_recovery_service.py).
   - Orchestrates database reconciliation + disk sweep.
   - Generates automated operational alert via `AlertingService` and in-app notification via `AppNotification`.
   - Produces a structured `RecoveryReport`:
     ```python
     @dataclass
     class RecoveryReport:
         orphaned_jobs_count: int
         orphaned_queue_items_count: int
         orphaned_broadcasts_count: int
         orphaned_video_jobs_count: int
         temp_files_deleted: int
         bytes_freed: int
     ```

4. **FastAPI Lifespan & Admin Router Integration**:
   - Hooked into `backend/main.py` lifespan on startup.
   - Exposed via `POST /api/jobs/recovery/sweep` in `backend/presentation/api/routers/jobs.py` for on-demand manual cleanup and telemetry by admins.

5. **Test-Driven Verification**:
   - Unit tests covering:
     - SQLite & Postgres queue items & broadcast reconciliation.
     - Disk orphan sweeper file deletion and safety guards.
     - `CrashRecoveryService` end-to-end flow with alert emission.
     - Full test suite passes.
